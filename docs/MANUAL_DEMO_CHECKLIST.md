# Manual Demo Preparation Checklist

Use this checklist to prepare the demo materials for PatraPilot AI. All materials should be clearly labeled as fictional and not contain real personal information.

## 1. Fictional Form (SIR-style in Hindi)

Create or obtain a fictional SIR-style (Small Industries Reservation) form in Hindi. The form should include fields for:
- Full Name
- Date of Birth
- Father's Name
- Mother's Name
- Address
- PIN Code

### Specifications:
- Clearly label as "FICTIONAL FORM - FOR DEMONSTRATION ONLY"
- Use fictional field names and instructions
- Do not copy any real government form
- Create a blank form template that users can fill
- Save as PDF or high-quality image (JPEG/PNG)
- Consider creating versions with different orientations (portrait/landscape) and quality levels

## 2. Fictional Supporting Documents

Create three types of fictional supporting documents that contain information matching the form fields:

### Document 1: Identity-Style Document
Should contain:
- Full Name: Kiran Demo
- Date of Birth: 15/08/1990
- Father's Name: Mohan Demo
- Mother's Name: Sita Demo
- Address: 123, Main Street, Anytown
- PIN Code: 110001

### Document 2: Alternative Identity Document (with variations)
Should contain:
- Full Name: Kiran Kumar Demo
- Date of Birth: 15/08/1990
- Father's Name: Mohan Lal Demo
- Mother's Name: Sita Devi Demo
- Address: 456, Second Street, Somewhere
- PIN Code: 110001

### Document 3: Conflicting Information Document
Should contain conflicting information for testing scenario C:
- Full Name: Mohan Demo (conflicting with Kiran)
- Date of Birth: 20/07/1991 (conflicting)
- Father's Name: Mohan Demo (same as above)
- Mother's Name: Sita Demo (same as above)
- Address: 789, Third Street, Elsewhere (conflicting)
- PIN Code: 400001 (conflicting)

### Specifications for all documents:
- Clearly label as "FICTIONAL DOCUMENT - FOR DEMONSTRATION ONLY"
- Use fictional data only
- Do not use real government templates or security features
- Create as PDF or high-quality images (JPEG/PNG)
- Include reasonable document-like formatting (borders, fields, etc.)
- Consider creating both clear and slightly blurred versions for robustness testing

## 3. Demo Scenarios Preparation

### Scenario A: Complete Fictional Profile
- Form: Blank fictional SIR-style form
- Supporting Documents: Document 1 and Document 2 (both contain complete, consistent information)
- Expected Outcome: All fields should be extractable and confirmable

### Scenario B: Missing Information
- Form: Blank fictional SIR-style form
- Supporting Documents: Document 1 but with certain information removed (e.g., remove date of birth from the document)
- Expected Outcome: Date of birth field should show as missing

### Scenario C: Conflicting Information
- Form: Blank fictional SIR-style form
- Supporting Documents: Document 1 and Document 3 (contain conflicting information)
- Expected Outcome: Fields with conflicts should be clearly marked as conflicting

## 4. Demo Script Hints

Prepare a brief script to guide your demonstration:

### Introduction (30 seconds)
- Introduce yourself and the team
- Explain the problem: people struggle with unfamiliar forms
- Introduce PatraPilot AI as a solution

### Demo Walkthrough (3-4 minutes)
1. **Language Selection**: Show how to switch to Hindi
2. **Form Upload**: Upload the fictional form
3. **Form Understanding**: Show how AI explains fields in simple Hindi
4. **Supporting Documents**: Upload the supporting documents
5. **Extraction & Mapping**: Show how AI extracts information and maps to fields
6. **Verification & Review**: Demonstrate confirming, correcting, and leaving fields blank
7. **Final Draft**: Show the completed draft with print option
8. **Scenario Switching**: Briefly show how to switch between demo scenarios

### Key Points to Emphasize
- The AI explains fields in simple language (not just translates)
- Information is extracted from user's own documents
- User maintains control: confirms, corrects, or leaves blank
- No information is invented or automatically selected
- Clear disclaimers that this is a demo, not an official service
- Privacy-focused: data doesn't leave the browser/session

## 5. Technical Preparation

### Before the Demo:
- [ ] Test the application on the demo machine
- [ ] Verify all languages work (English, Hindi, Marathi)
- [ ] Test form upload with your fictional form
- [ ] Test document upload with your fictional documents
- [ ] Verify the three demo scenarios work as expected
- [ ] Test print functionality
- [ ] Check that the disclaimer is visible in the final draft
- [ ] Ensure no real personal information is anywhere in the demo materials

### Day of Demo:
- [ ] Bring a copy of the demo materials on a USB drive
- [ ] Have the application pre-loaded on a laptop or be ready to clone and install
- [ ] Consider having a backup demo device
- [ ] Prepare to explain the mock vs. live AI distinction if asked
- [ ] Have your demo script ready but be flexible

## 6. Safety and Ethics Reminders

- [ ] All demo materials are clearly labeled as fictional
- [ ] No real personal information is used in any demo
- [ ] No real government forms or documents are copied
- [ ] The application does not claim to be an official government service
- [ ] All outputs include appropriate disclaimers
- [ ] We do not guarantee that the draft will be accepted by any office
- [ ] Users are reminded they are responsible for reviewing all information

## 7. Optional Enhancements

If time allows, consider preparing:
- A short video demo showing the complete flow
- Printed cards with key talking points
- A one-page flyer explaining the project
- Backup power adapter and mouse for the demo laptop
- Water and notes for yourself during the presentation

Remember: The goal is to clearly demonstrate the concept and workflow, not to have perfect execution. Focus on communicating the value proposition and how the application helps users.
